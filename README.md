## How I Work

I treat architecture as a product capability, not a diagram. Good boundaries
should make features safer to change, incidents easier to investigate, and
delivery more predictable.

I use AI as an engineering tool for context exploration, test design, review
checklists, debugging hypotheses, and documentation. The final technical
decision remains grounded in code, tests, measurements, and product constraints.

## Current Direction

- Expanding shared mobile architecture with Kotlin Multiplatform.
- Applying AI to engineering workflows without delegating technical judgment.
- Building small, verifiable proofs before proposing large platform changes.
- Making technical impact visible through documentation, tests and measurable outcomes.
